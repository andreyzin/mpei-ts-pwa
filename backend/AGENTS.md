# Инструкции бэкенда

## Слои

- Разделяй роутеры (HTTP), схемы (валидация/сериализация), сервисы (бизнес-правила) и репозитории (доступ к данным).
- Роутер должен быть тонким: разобрать запрос, вызвать сервис, преобразовать результат и вернуть ответ.
- Не помещай бизнес-логику в Pydantic-модели, middleware или обработчики исключений.
- Зависимости FastAPI используй для явной передачи настроек, авторизации и ресурсов запроса.

## Python

- Соблюдай типизацию: аннотации обязательны для публичных функций и границ слоёв.
- Пиши небольшие функции без скрытых побочных эффектов; чистые преобразования выноси отдельно.
- Не используй изменяемые значения по умолчанию и широкие `except Exception`.
- Конфигурацию загружай из окружения через единый объект настроек; не читай `os.environ` по всему коду.
- Валидируй данные на входе и возвращай доменные ошибки через единый механизм.

## API и безопасность

- Все внешние данные валидируются Pydantic-схемами; не принимай произвольные словари без причины.
- Указывай response model, коды статуса и понятные сообщения ошибок.
- Не логируй токены, пароли, персональные данные и полные тела запросов без необходимости.
- CORS, авторизацию, лимиты и таймауты настраивай явно; production-значения не должны быть permissive.

## Тестирование

- Тестируй сервисы отдельно от HTTP и добавляй интеграционные тесты для критичных endpoint.
- Каждый баг фиксируй регрессионным тестом.
- Не завязывай тесты на порядок выполнения, реальные внешние сервисы или текущее время без фикстур/моков.
